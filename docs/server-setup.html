Apply Agent Server Setup

You're putting a job-application agent on a computer at home that runs every night on its own. You'll control it from your laptop over Tailscale and get a summary on your phone in the morning. This guide assumes you've never done any of it before: every command is here, and it says where to type it.

The big picture

Three computers are involved. The server does all the work: it finds jobs, fills in applications in a real Chrome browser, and keeps a record of everything. Your laptop only talks to it, to set it up, check on it and stop it. Your phone gets a message when each night is done.

Tailscale is the private, encrypted link between your laptop and the server. It means you can reach the server from anywhere, home or away, without opening anything on your home router. The server still reaches job sites and Telegram over the normal internet.

How the agent turns a posting into an application

Everything starts from one file, src/personas.js, which says who you are and which job titles you want. The agent finds postings that match, then works through them one at a time in a real Chrome browser, filling in each company's own form from your answers. Every job it touches is recorded, so it never applies to the same job twice.

What happens each night

You won't run the agent by hand once it's set up. cron, the Linux scheduler, starts the nightly orchestrator at the time you pick. The orchestrator takes each persona in turn, running a short round for each, until every persona reaches its target or the night's time is up. Then it sends one message to your phone.

What you need

The server

  • A computer that can stay on all the time, with an Intel or AMD (x86-64) processor. Chrome has no Linux version for ARM chips, so a Raspberry Pi won't work.
  • 8 GB of memory (4 GB works for one browser at a time) and 30 GB of free disk.
  • On your home internet if you can. Job sites flag cloud-server addresses more often than home connections.
  • A USB stick to install Ubuntu, plus a screen and keyboard for the first 20 minutes only.

Your laptop and phone

  • A terminal: Terminal on a Mac, or PowerShell on Windows. Both already have ssh.
  • Tailscale: a free account, and the app on your laptop.
  • RealVNC Viewer (free), used once in step 7.
  • Optional but recommended: VS Code with the Remote - SSH extension, to edit files on the server comfortably.
  • Telegram on your phone, for the morning summary.
  • Your resume as a PDF, a Google account and a LinkedIn account.

Total time: about 1½–2 hours, most of it waiting for installs.

01Install Ubuntu and Tailscale

At the server, with a screen and keyboard · 30 min

  1. Download Ubuntu Server 24.04 LTS and write it to a USB stick (balenaEtcher or Rufus work).
  2. Boot the server from the stick and follow the installer. When asked, create your user (you) and tick Install OpenSSH server.
  3. After it restarts, log in at the server's own keyboard and install Tailscale:
At the server's keyboard
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up

tailscale up prints a link. Open it on your laptop or phone and sign in with the same Tailscale account as your laptop.

  1. Open the Tailscale admin console, find the new machine, and choose … → Edit machine name. Name it jobserver.

You can unplug the screen and keyboard now. Everything from here happens from your laptop.

02Connect from your laptop

On your laptop · 5 min

Make sure Tailscale is running and signed in on your laptop, then open a terminal and connect:

On your laptop
ssh {USER}@{HOST}

The first time, type yes to trust the server, then your Ubuntu password. Your prompt changes to {USER}@{HOST}: you're now typing on the server. exit brings you back.

"Could not resolve hostname"? On the server, run tailscale ip -4 and use the 100.x.y.z address it prints instead of the name.

Optional, recommended: in VS Code, install Remote - SSH, open the command palette (Ctrl/Cmd+Shift+P), choose Remote-SSH: Connect to Host… and enter you@jobserver. You can then open folders and files on the server as if they were on your laptop, and its built-in terminal is already on the server.

03Install the tools

On the server (over ssh) · 10 min

This installs Google Chrome, a virtual screen for Chrome to draw on (xvfb), a way to view that screen once (x11vnc), and Node.js, which the agent is written in. Paste it all at once:

On the server
sudo timedatectl set-timezone UTC
sudo apt-get update
sudo apt-get install -y git curl python3 xvfb x11vnc
wget -q https://dl.google.com/linux/direct/google-chrome-stable_current_amd64.deb
sudo apt-get install -y ./google-chrome-stable_current_amd64.deb
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.nvm/nvm.sh
nvm install 22
node -v

The last line should print v22.something. The first line sets the server's clock to UTC so the schedule in step 10 is easy to read. Skip it if this machine already runs other scheduled things.

04Download the agent

On the server · 2 min

On the server
git clone https://github.com/fgbosibo17/Apply-Agent.git ~/job-agent
cd ~/job-agent

This makes your own copy in ~/job-agent. Your edits stay on your server: you can't push changes back to this repo, so your details can't end up public by accident.

05Build your persona

Laptop + server · 20–30 min

A persona is you, as the agent presents you: your contact details, your answers to the usual application questions, your resume, and the job titles you're after. It lives in src/personas.js, which ships with placeholders such as <FILL_ME_IN> that you replace.

Copy your resume to the server

On your laptop
scp ~/Downloads/My_Resume.pdf {USER}@{HOST}:job-agent/Resume/

Change ~/Downloads/My_Resume.pdf to where your resume actually is. On Windows that might be $HOME\Downloads\My_Resume.pdf. With VS Code Remote-SSH you can drag the file into the Resume folder instead.

Fill in src/personas.js

Open it in VS Code (Remote-SSH → Open Folder → ~/job-agent), or on the server with nano ~/job-agent/src/personas.js (Ctrl+O saves, Ctrl+X exits). Fill in three blocks: common, identityA and the primary persona. Leave adjacent and secondary exactly as they are: the agent skips examples you haven't filled in.

FieldWhat to put
firstName, lastName, fullName, email, phoneDigits, phoneFull, linkedInYour real contact details, exactly as on your resume.
city, state, stateFull, zipWhere you live. Used for "where are you located?" and hybrid jobs near you.
authorizedUS, usCitizen, workAuthStatus, needsSponsorship…Your work authorization, truthfully. Jobs open only to US citizens are skipped if usCitizen isn't 'Yes'.
gender, race, pronouns, veteranStatus, disabilityStatusVoluntary equal-opportunity answers. Fill them in, or leave the <…> placeholder: the agent then picks "decline to answer", never a guess.
resumePathChange <Your_Resume.pdf> to your file's exact name, e.g. My_Resume.pdf. Capital letters must match.
currentEmployer, currentTitle, totalYearsExperienceFrom your resume.
salaryMin, salaryMax, salaryTarget, salaryRangeStringYour range. The string is what forms get when they ask, e.g. '$80,000 - $105,000'.
elevatorPitch, whyThisRoleBlurb, reasonForLeavingOne or two honest sentences each. They answer open questions on forms.
targetRolesJob titles to search for, e.g. ['Operations Analyst remote', 'Business Analyst remote'].
matchKeywordsWhich job titles count as a match, written as /Title one|Title two|Title three/i. This decides which jobs get applied to, so make it specific.
skillsSkills that are really on your resume, separated by |, e.g. 'Excel|SQL|Tableau'. "How many years of X?" gets your real total for these, and 0 for anything else.

Here's what a filled-in primary block looks like, with made-up values:

Example · src/personas.js
  primary: {
    ...common,
    ...identityA,
    persona: 'primary',
    resumePath: path.join(RESUME_DIR, 'My_Resume.pdf'),
    resumeDocx: path.join(RESUME_DIR, 'My_Resume.docx'),
    currentEmployer: 'Example Logistics',
    currentTitle: 'Operations Analyst',
    totalYearsExperience: 6,
    salaryMin: 80000,
    salaryMax: 105000,
    salaryTarget: 95000,
    salaryRangeString: '$80,000 - $105,000',
    reasonForLeaving: 'Looking for a remote role with more ownership of reporting.',
    whyThisRoleBlurb: 'I like turning messy operations data into decisions. Six years of reporting and process work have made me quick with SQL and dashboards.',
    elevatorPitch: 'Operations analyst with 6 years in logistics reporting, SQL and dashboards.',
    targetRoles: ['Operations Analyst remote', 'Business Analyst remote', 'Data Analyst remote'],
    matchKeywords: /Operations Analyst|Business Analyst|Data Analyst/i,
    skills: 'Excel|SQL|Tableau|Power BI',
  },

Check your work. This catches typos, and shows whether your target titles route to your persona:

On the server
cd ~/job-agent && node src/check-personas.js

Your line should show your name, email and resume OK. A red error pointing at a line number means a missing quote or comma on that line.

06Check the server is ready

On the server · 3 min

On the server
cd ~/job-agent && bash scripts/bootstrap.sh

It installs the agent's dependencies, then prints a checklist. Each problem comes with the fix.

At this point you should see [ok] for node, Chrome, xvfb, disk and resume:{PERSONA}. Two other things are normal for now:

  • [warn] resume:adjacent and resume:secondary: the examples you left alone.
  • [FAIL] profile:{PERSONA}: … Nobody has logged in: that's the next step.

07Log in to Google and LinkedIn, once

Laptop + server · 10 min

The agent uses a real Chrome browser with its own saved logins (a browser profile). Some job sites email a security code before you can submit, and the agent reads it from Gmail in that same browser. So the browser needs to be signed in to your Google account once. The server has no screen, so you'll look at its virtual screen from your laptop through a tunnel inside Tailscale:

a. On the server, start the login screen. It waits while you sign in:

On the server
cd ~/job-agent && bash scripts/login-profile.sh {PERSONA}

b. On your laptop, open a second terminal window and start the tunnel. It prints nothing; leave it open:

On your laptop
ssh -N -L 5900:localhost:5900 {USER}@{HOST}

c. Open RealVNC Viewer and connect to localhost:5900. If it warns that the connection is unencrypted, continue: the ssh tunnel is already encrypting it. You'll see a Chrome window.

d. Sign in to Google (Gmail) in the first tab, then LinkedIn in the second. Then close the Chrome window with its ×. The server prints Chrome closed — profile saved. Stop the tunnel with Ctrl+C.

e. Confirm Google stuck:

On the server
python3 scripts/gmail-session-check.py

You want ✅ {PERSONA}: Gmail signed in.

Never copy this browser folder to another computer. It holds live logins, and a copied profile looks like a different device, which is exactly what bot detection looks for. If a login ever expires, run this step again.

08Do a practice run

On the server · 15 min

First fill the agent's list of companies to search (it starts empty), then let it fill in three real application forms without submitting them:

On the server · sends nothing
cd ~/job-agent
npm run seed
bash scripts/nightly-run.sh {PERSONA} --max 3

The practice run takes 5–10 minutes and ends with a summary in curly brackets. Look for "dryRun": 3. A practice run never uses up a job: the real run can still apply to it later.

Now look at what it filled in. In VS Code, open .state/runs/dryrun/ and click each picture. Or copy the pictures to your laptop:

On your laptop
mkdir -p dryrun && scp "{USER}@{HOST}:job-agent/.state/runs/dryrun/*.png" dryrun/

Read each form as if you were the recruiter. If an answer is wrong, fix it in src/personas.js and run the practice again. When you're happy, you can send one real application as a final test:

On the server · submits a real application
bash scripts/nightly-run.sh {PERSONA} --live --max 1

09Morning summary on your phone

Phone + server · 10 min · optional

  1. In Telegram, open a chat with @BotFather, send /newbot, and give it a name and a username ending in bot. It replies with a token like 123456:ABC-….
  2. Open your new bot's chat and press Start (or send it "hi").
  3. Find your chat id. Put your token in this command and look for "chat":{"id": followed by a number:
On the server
curl -s "https://api.telegram.org/botPASTE_TOKEN_HERE/getUpdates"
  1. Save both where the agent reads them, outside the repo, readable only by you:
On the server
cat > ~/.telegram_notify_credentials <<'EOF'
TELEGRAM_BOT_TOKEN=PASTE_TOKEN_HERE
TELEGRAM_CHAT_ID=PASTE_CHAT_ID_HERE
EOF
chmod 600 ~/.telegram_notify_credentials
  1. Send yourself a test message:
On the server
cd ~/job-agent
echo '{"ranAt":"20261001T060000Z","mode":"--dry-run","results":[]}' > /tmp/test-summary.json
python3 scripts/notify-telegram.py /tmp/test-summary.json

Your phone gets "Job Apply run finished … (DRY RUN)". From now on you'll get one of these after every night, plus a warning if Google ever signs the browser out.

10Put it on a schedule

On the server · 5 min

cron runs commands at set times. It starts programs with almost no settings, so first print the line that tells it where Node.js lives:

On the server
echo "PATH=$(dirname "$(which node)"):/usr/local/bin:/usr/bin:/bin"

Copy the line it prints. It starts with PATH=/home/{USER}/.nvm/.

Open your schedule with crontab -e (pick nano if it asks), go to the bottom, and paste this. Then replace the first line with the one you just copied:

crontab -e · submits real applications nightly
PATH=/home/{USER}/.nvm/versions/node/v22.0.0/bin:/usr/local/bin:/usr/bin:/bin
PERSONAS={PERSONA}
TARGET=25
NEXT_START_UTC=06:00
0 6 * * *  cd /home/{USER}/job-agent && mkdir -p .state/runs/logs && bash scripts/nightly-orchestrator.sh --live >> .state/runs/logs/cron.log 2>&1

Save with Ctrl+O, Enter, exit with Ctrl+X. crontab -l shows what's saved.

LineWhat it means
PATH=…Where to find Node.js.
PERSONAS={PERSONA}Run only your persona, not the unfilled examples.
TARGET=25Applications per night. Start small, raise it once you trust the answers.
NEXT_START_UTC=06:00Must match the start time on the last line. The run stops 15 minutes before the next one would begin.
0 6 * * *Minute 0, hour 6, every day: 06:00 UTC.
--liveActually submit. Without it, every night is a practice run.

06:00 UTC in US time zones. Clocks go back in November, so winter is an hour earlier:

Time zoneSummer (Mar–Nov)Winter (Nov–Mar)
Eastern2:00 am1:00 am
Central1:00 ammidnight
Mountainmidnight11:00 pm
Pacific11:00 pm10:00 pm

To start at a different time, change the hour in both places: 0 7 * * * with NEXT_START_UTC=07:00 starts an hour later.

11Control it from your laptop

You never need to log in to the server for day-to-day things. Each of these runs one command on the server over Tailscale and shows you the answer. They work as-is in Mac Terminal and Windows PowerShell.

How did last night go?

On your laptop
ssh {USER}@{HOST} "cd job-agent && . scripts/lib/ensure-node.sh && npm run -s agent -- digest --since 1d --format telegram"

Is it running right now?

On your laptop
ssh {USER}@{HOST} "tail -n 40 job-agent/.state/runs/logs/cron.log"

Stop it now

On your laptop
ssh {USER}@{HOST} "cd job-agent && bash scripts/stop-now.sh"

The job in progress finishes first, so nothing is left half-submitted. Tomorrow night still runs as scheduled.

Apply to 10 more right now

On your laptop · submits real applications
ssh {USER}@{HOST} "cd job-agent && nohup bash scripts/persona-push.sh {PERSONA} 10 --live > /dev/null 2>&1 &"

Is Google still signed in? Is the machine healthy?

On your laptop
ssh {USER}@{HOST} "cd job-agent && python3 scripts/gmail-session-check.py"
ssh {USER}@{HOST} "cd job-agent && . scripts/lib/ensure-node.sh && npm run -s doctor"

Pause the schedule

Run ssh {USER}@{HOST}, then crontab -e, and put a # at the very start of the 0 6 * * * line. Remove the # to resume.

12Update to a new version

The agent never updates itself, so nothing changes under you in the middle of a night. When there's a new version (see the releases page), update during the day:

On the server
cd ~/job-agent && git stash && git pull && git stash pop && npm ci

git stash sets your persona edits aside while the new version comes in, and git stash pop puts them back. If it reports a conflict, stop there and ask for help before running anything else.

When something goes wrong

What you seeWhat it meansWhat to do
No Telegram message in the morningThe night didn't start, or Telegram isn't set upCheck crontab -l, then read the log with the "Is it running?" command. Redo step 9's test.
node not found in the logcron can't find Node.jsRedo the PATH= line in step 10.
❌ NOT signed in to GoogleGoogle signed the browser outRedo step 7. Jobs that email a code are skipped until you do.
Nobody has logged in as …The browser profile is emptyStep 7.
persona "…" is not set upsrc/personas.js still has placeholders for that personaFinish step 5, or check PERSONAS= in your crontab.
another run holds the browser profileA run is still going, or one crashedWait for it, or run "Stop it now". If it's definitely dead: npm run agent -- round unlock --force --persona {PERSONA}.
0 applied every nightNo matching jobs, or everything is being skippedRun "How did last night go?" and read the skip reasons. Try npm run seed, and check that matchKeywords isn't too narrow.
Chrome crashed in step 7Usually a container or a locked-down VMUse a normal Ubuntu install or VM. Chrome's sandbox doesn't run inside a default Docker container.
VNC shows nothing or won't connectThe tunnel isn't running, or the login script endedKeep both terminals from step 7 open at the same time, and connect to localhost:5900, not the server's name.

Rules that keep you safe

Practise before --live. After any change to your persona, run a practice and read the screenshots. --live sends real applications to real employers under your name.

Your details stay on your server. src/personas.js and your resume hold your name, email and phone. Don't upload them anywhere or paste them into a public repo.

Let the server do the applying. If you also run the agent on your laptop, the two keep separate records and can apply to the same job twice. Use the laptop only to control the server.

Keep the server patched. Once a month, during the day: sudo apt-get update && sudo apt-get upgrade -y. This also updates Chrome.

Don't open ports on your router. Tailscale is how you reach the server from anywhere; nothing needs to be exposed to the internet.

Words used in this guide

Persona
You as the agent presents you: contact details, answers, resume and target job titles, in src/personas.js.
Discovery
Searching job-board APIs and public lists for new postings that match your titles.
Queue
The list of jobs waiting to be tried: queue-{PERSONA}.json.
Round
One persona's turn at applying. It has an id like rnd_20261001_ab12cd34.
Practice run
Also called a dry run. Fills the form and takes a screenshot without submitting. This is the default.
--live
The switch that makes a run submit for real.
Browser profile
Chrome's folder of saved logins on the server (browser-profile-{PERSONA}). Made once, in step 7.
Lock
A marker that stops two runs from using the same browser profile at once.
Ledger
The record of every job the agent has seen or applied to, in .state/. It's what prevents duplicates.
Digest
The summary of a run: how many applied, skipped and failed.
cron
Linux's built-in scheduler.
Tailscale
A private network between your own devices, so your laptop can reach the server from anywhere.
ssh
Typing commands on another computer through your own terminal.
VNC
Seeing and using another computer's screen. Used once, to log in.
